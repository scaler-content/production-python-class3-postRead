What to noticeSome mistakes are caught before the program runs, and some only when a row is read or a reply is checked. The earlier the catch, the cheaper the fix. A bad row is refused and listed; it never silently disappears.

How the class climbed, in order

    
    
      
  1. BlueprintsA class holds one case. __init__ sets it up, and self means the object being built.
    2. 
      
  2. Records that check themselves@dataclass writes the boilerplate. frozen=True makes facts read-only, and enums fix the allowed values.
    3. 
      
  3. Type checks before the runmypy reads the whole program. It found a dictionary habit and a date sent where text was expected.
    4. 
      
  4. Promises as testspytest runs named checks. A broken row fails a test, and the test says which promise broke.
    5. 
      
  5. One door to the modelThe rules never import the model. The call is bounded, and a missing key falls back to a recorded answer.
    6. 
      
  6. A baseline by handTen golden cases, four measures, scored without a second model.

Python: records and types

  

  

    
You wantWriteWhat it does

    
A class with setupclass Case: and def __init__(self, ...)Blueprint, and the setup that runs when you call Case(...)

    
A record with less typing@dataclass above the classWrites __init__, __repr__ and == from the fields

    
A read-only record@dataclass(frozen=True)Attempts to change a field raise an error

    
A list that starts emptyfield(default_factory=list)Each object gets its own list

    
A closed set of valuesclass OrderStatus(StrEnum)Unknown values raise ValueError

    
A value that may be missingShipmentInfo | None = NoneCode using it must decide what None means

    
Hide a secret from printoutsfield(default=None, repr=False)The value is left out of print and error messages
